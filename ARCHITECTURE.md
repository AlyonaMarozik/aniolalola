# Сад — архитектура данных

Четыре независимые сущности:

- **Inventory** — личные экземпляры, покупки, статусы и `source_of_purchase`.
- **Catalog** — независимые от пользователя виды/сорта, свойства, изображения и ссылки на источники.
- **Garden Fact** — фактические посадки, координаты и история изменений.
- **Garden Plan** — проектные размещения, черновики, закрепления и временные кандидаты.

Связи: `inventory.catalog_id → catalog.plant_id`; `garden_fact.inventory_item_id → inventory.item_id`; `garden_plan.inventory_item_id → inventory.item_id` (nullable для примерки кандидата из Catalog).

**Правила:** скраперы пишут только в Catalog. Catalog никогда не обновляет Inventory или план. Garden Fact не меняется при закреплении Garden Plan. Посадка — отдельная подтверждаемая операция с историей. Один сорт может иметь несколько экземпляров Inventory и несколько посадок.

## Текущее состояние

Рабочая карта пока остаётся в `index.html` с localStorage `sad-planner-v9` — не менять ключ и не удалять данные при миграции. Встроенный inventory и fact являются legacy-данными до отдельного переноса. Миграция только с резервной копией и проверкой.

## План импорта

Первый источник Catalog — sadzawka.pl. Перед обходом проверить robots.txt, условия использования и права на фотографии. Импортировать в staging с исходными URL, timestamp, сырыми именами и provenance, затем нормализовать и дедуплицировать. Другие источники обнаруживать через `inventory.source_of_purchase`, но не сканировать автоматически без проверки.

Для роста: SQLite как источник истины Catalog; статические JSON-экспорты для GitHub Pages; изображения вне SQLite с атрибуцией и разрешениями.
